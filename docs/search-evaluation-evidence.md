# Lexical Search Evaluation Evidence

The repository publishes revision-bound lexical-search regression evidence from `platform/apps/api/scripts/evaluate_search.py`.

## Purpose

This evidence is an engineering regression signal. It is intended to detect whether a code change degrades the repository's small, deterministic lexical-search fixture.

It is **not** evidence of production retrieval quality, Arabic corpus coverage, RAG answer quality, groundedness, human preference, or product-market fit.

## Current evaluator gate

The evaluator exits non-zero when any of these conditions is violated:

- `MRR@10 < 0.85`
- `Recall@5 < 1.0`
- `zero_result_rate > 0.0`

Those thresholds are regression gates for the maintained fixture, not production SLOs.

## Published artifact

The workflow `.github/workflows/search-evaluation-evidence.yml` runs the existing evaluator and uploads an artifact named:

`phase3-search-evaluation-<tested_sha>`

The artifact contains:

- `metrics.json` — evaluator metrics generated by the existing search evaluator.
- `provenance.json` — tested SHA, source head SHA, base SHA when applicable, workflow run identity, event type, and explicit evidence limitations.

For pull requests, the default GitHub checkout tests the pull-request merge revision represented by `github.sha`; the source branch head is recorded separately in provenance. For pushes to `main`, the tested SHA is the pushed revision.

## Interpretation rule

A passing artifact means only that the tested revision passed the repository's lexical regression fixture. Do not convert a PASS into a claim that search is production-ready. Human benchmark evidence and larger corpus-level evaluation remain separate gates.
