# AISearcharab — Security Contract

## Trust model

- Browser input, headers, identifiers and content are untrusted.
- Database credentials and cryptographic keys are server-only.
- Authentication uses opaque server-side sessions; raw session tokens are not persisted in the database.
- Privileged roles require MFA in staging/production configuration.
- Mutations require CSRF; sensitive mutations additionally require step-up authentication.
- Authorization is role/permission based and must be checked server-side for every privileged route.

## Transport controls

- explicit CORS origins;
- TrustedHost allowlist;
- hard request-body ceiling for declared and streamed/chunked requests;
- privacy-safe request IDs/logging;
- CSP, `nosniff`, frame denial, no-referrer, Permissions-Policy, COOP/CORP, DNS-prefetch disablement and no-store;
- HSTS when secure cookies are enabled.

## Input contracts

FastAPI/Pydantic models are the API boundary validator. Slugs/sections use bounded patterns, local URL paths reject external/protocol-relative paths, source URLs use HTTP URL types, query/page limits are bounded and production configuration fails closed on unsafe hosts/origins/database settings.

## Browser rendering

Privileged JavaScript must not use HTML execution sinks (`innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`) or dynamic code execution (`eval`, `new Function`). Persistent browser storage is forbidden for privileged state/session material. CI scans these patterns.

## Files and storage

There is currently no application upload/storage route. MIME validation, magic-byte inspection, image re-encoding and signed download URLs are therefore not claimed. Adding file storage requires a separate security design and tests before any endpoint is exposed.

## Database authorization

The database is not exposed directly to the browser. Server-side API RBAC is the authorization boundary. PostgreSQL RLS is not claimed. Any future direct client-to-database architecture is forbidden until deny-by-default RLS policies and per-request identity propagation are implemented and tested.

## Supply chain

- Python runtime dependencies are pinned and the resolved graph is hashed/audited.
- CycloneDX SBOM and VEX-aware audit evidence are generated by CI.
- GitHub Actions used by canonical workflows are pinned to immutable commits.
- Container base images are digest-pinned.
- checkout credentials are not persisted.
- repository/tree and reachable Git history secret scans remain release gates.

## Incident evidence

Audit events record actor, action, outcome, target, request ID, sanitized metadata and timestamp. Raw credentials, cookies, OTPs, recovery codes, tokens, request bodies and raw search queries must not enter logs or release evidence.

## Production-only controls

Distributed rate limiting/WAF, managed PostgreSQL/PITR/restore, external secrets, observability/alerting, live TLS/DNS verification and independent security testing are environment controls. They remain fail-closed release gates rather than simulated booleans in application code.
